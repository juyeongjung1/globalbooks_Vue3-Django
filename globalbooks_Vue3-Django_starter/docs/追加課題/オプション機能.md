# オプション機能（任意課題）

基本の一覧・検索・詳細・登録・編集・削除を完成させた後、次の3つから選択して取り組みます。
オプションが未実装でも、基本課題は完成です。詳細検索など、ここにない機能の追加は必要ありません。

| 課題 | 内容 | 主に応用する学習内容 | 追加で学ぶ内容 |
| --- | --- | --- | --- |
| 1 | 並び替えボタン | `ref`、`@click`、Axiosの`params`、一覧取得 | Djangoの`order_by()` |
| 2 | いいね | ボタン、AxiosのPOST、取得したデータの表示 | `@action`、`F()`による加算 |
| 3 | 画像ファイル添付 | 入力フォーム、`ref`、Axios、`try/catch` | ファイル入力、`FormData`、画像検証・保存 |

学習済みの `ch05-crud` と同じように、各Vueファイルで処理を書きます。
API用の共通クラスや状態管理ライブラリは必要ありません。3つの機能は独立して実装できます。

## 最初から用意するDB項目

アプリケーションのテーブルは `books` だけです。
いいね用の `like_count` は、基本課題のモデル作成時点で次の定義を含めます。

```python
like_count = models.PositiveIntegerField(default=0)
```

初期SQLの10件もすべて0です。基本課題をこの教材で始めれば、オプション開始時の列追加は不要です。
新規登録時は自動的に0になるため、利用者が回数を入力する必要もありません。

`BookSerializer` の `class Meta` に `read_only_fields = ['like_count']` を指定します。
通常の登録・編集で回数を変更せず、いいねAPIで増やします。

旧版で既にDBを作成した環境だけはモデル変更後のマイグレーションが必要です。
解答にはそのためのマイグレーションを含めてあります。新しい列の値は0になり、既存書籍を保持します。

## 1. 並び替えボタン

### 完成時の動作

一覧画面に次のボタンを配置します。選択中のボタンは色を変えます。

| ボタン | APIへ送る `ordering` |
| --- | --- |
| IDが小さい順 | `id` |
| IDが大きい順 | `-id` |
| 価格が安い順 | `price` |
| 価格が高い順 | `-price` |
| 書籍名の昇順 | `title` |
| 書籍名の降順 | `-title` |
| いいねが多い順 | `-like_count` |

- 初期表示はIDが小さい順です。
- キーワード検索と並び替えを組み合わせます。並び替えても検索条件を保持します。
- 同じ価格・書籍名・いいね数の場合は、IDが小さい順にします。
- 未指定・未対応の `ordering` はIDが小さい順にします。
- 書籍名はDBの文字列順です。読み仮名による五十音順は扱いません。
- いいね機能が未実装でも、いいね数の列は存在します。全件0ならID順になります。

### 実装の進め方

1. `BookListView.vue` に並び順を保持する `ref` とボタンを追加する。
2. ボタンで並び順を変更し、既存の一覧取得関数を呼び出す。
3. Axiosの `params` に `keyword` と `ordering` を渡す。
4. Djangoの `get_queryset()` で検索した後、許可した項目だけを `order_by()` に渡す。

例：`GET http://localhost:8000/api/books/?keyword=Vue&ordering=price`

### 確認項目

- [ ] 各ボタンで期待する順序になる
- [ ] 検索結果だけが並び替わる
- [ ] 同じ価格などの書籍でも順序が安定する
- [ ] 検索結果0件でもエラーにならない

## 2. いいね

### 完成時の動作

一覧・詳細画面に「いいね」ボタンと現在の回数を表示します。

- 1回の成功したリクエストにつき、DBの現在値を1増やします。
- ユーザー管理はなく、同じ人が何回押しても構いません。
- 取り消し・1人1回の制限は実装しません。
- 再読み込み後も回数を保持します。
- 通信に失敗した場合は、表示上だけ回数を増やさず、エラーを表示します。
- 送信中はボタンを無効にします。完了後は再び押せます。
- 通常の書籍編集をしても、いいね数を維持します。

### API

`POST http://localhost:8000/api/books/{id}/like/`

送信する本文は不要です。成功時は更新後の書籍オブジェクトを200で返します。
存在しない書籍は404です。クライアントから「合計回数」を送る方式にはしません。

### 実装の進め方

1. `BookViewSet` に `@action(detail=True, methods=['post'])` を使った `like` を追加する。
2. `self.get_object()` で対象を取得する。
3. `F('like_count') + 1` を使い、DB内で加算する。同時に押された場合の更新の取りこぼしを防ぐ。
4. DBから読み直し、Serializerを使って更新後の書籍を返す。
5. VueからAxiosのPOSTで呼び出し、成功したレスポンスまたは一覧再取得で表示を更新する。

一覧で再取得する場合も、検索条件・並び順を保持します。
「いいねが多い順」を選んでいる場合は、回数に合わせて並び順も更新します。

### 確認項目

- [ ] 3回押すと0→1→2→3になる
- [ ] 再読み込み、一覧と詳細の移動、通常の編集でも回数が残る
- [ ] いいねが多い順と組み合わせられる
- [ ] 通信エラーを表示できる

## 3. 画像ファイル添付

### VueとDjangoの役割

**Vueがファイルの選択・送信を行い、Djangoが画像の検証・保存を行います。**
ファイルの実体は `backend-django/media/books/` に置き、DBには既存の `image_path` でURLを保存します。
画像用のテーブルや列は追加しません。

### 完成時の動作

新規登録・編集画面に、任意のファイル入力を追加します。

- JPEG・PNG、1ファイル5MB以下（5 × 1024 × 1024バイト）とする。
- ファイルを選択した場合は、手入力の画像パスより優先する。
- 選択しない場合は、従来どおり画像パスを使う。編集時も現在の値を保持する。
- 両方未指定なら「画像なし」を表示する。
- 一覧・詳細画面で、アップロード画像を表示できる。
- 画像の送信に失敗した場合は、書籍の登録・更新へ進まない。

### Django側の準備

画像を検証するPillowをインストールします。基本課題だけの場合は不要です。

```powershell
python -m pip install "Pillow>=11.1,<13"
```

`config/settings.py` に保存先を設定します。

```python
MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'
```

開発中に画像を配信するため、`config/urls.py` へ追加します。

```python
from django.conf import settings
from django.conf.urls.static import static

# urlpatternsの定義後に追加
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

### API

`POST http://localhost:8000/api/books/upload-image/`

- `multipart/form-data` で、`image` という名前の項目に画像を送る。
- 成功時は201で `{"image_path": "http://localhost:8000/media/books/保存名.png"}` を返す。
- 画像なし・画像ではないファイル・JPEG/PNG以外・5MB超過は400とする。
- `ImageUploadSerializer` の `ImageField` で画像として読み込めることを検証する。
- 保存にはDjangoの `default_storage` を使う。UUIDと検証済みの形式から保存名を作り、元のファイル名が同じでも上書きしない。

### Vue側の実装順序

1. `<input type="file" accept="image/jpeg,image/png">` の `@change` でファイルを取得する。
2. 選択したファイルを `ref<File | null>(null)` に保持する。形式・サイズも確認する。
3. 登録・保存ボタンを押したら、まず通常の書籍入力をチェックする。
4. ファイルがある場合は `FormData` に `image` を追加し、画像アップロードAPIへPOSTする。
5. 返されたURLを `image_path` に設定する。
6. 既存の書籍登録POST・更新PUTを、従来どおりJSONで送る。
7. 保存に成功したら、基本課題と同じ画面へ遷移する。

`Content-Type` ヘッダーは手動で設定しません。ブラウザがmultipartの区切り情報を付けます。
ファイル入力には `v-model` を使わず、`@change` を使います。

画像アップロードと書籍保存は別の通信です。書籍保存だけが失敗した場合、画像は保存済みなので、取得したURLを保持して再試行します。
本演習では、書籍削除・画像差し替え時の古い画像や、未使用画像の自動削除は対象外です。

### 確認項目

- [ ] 新規登録・編集で添付画像が保存・表示される
- [ ] 再読み込みしても画像が表示される
- [ ] ファイル未選択でも従来の画像パス入力で保存できる
- [ ] 画像ではないファイル・GIF・サイズ超過を拒否する
- [ ] 同名ファイルを送っても別の画像を上書きしない
- [ ] 画像送信に失敗した場合、書籍データを保存しない
